# Profile embedding service

The API uses `@xenova/transformers` 2.17.x and `Xenova/all-MiniLM-L6-v2`. The model is loaded lazily once per Node process on the first embedding request. `warmUpEmbeddingModel()` is available for a future worker entry point; the current API has no worker process, so API startup does not download model files. The first actual use needs network access to the model host and writable Hugging Face/Transformers cache storage. The library manages its cache using its default cache directory.

`buildStartupEmbeddingText` includes startup name, pitch, description, domains, stage, mentorship needs, and goals. `buildMentorEmbeddingText` includes current role, organization, bio, experience summary, years of experience, domains, skills, mentorship stages, and topics. Both normalize whitespace and sort/deduplicate taxonomy labels. They exclude account identifiers, email, availability, URLs, timestamps, approval state, and private admin data.

The Sprint 3.3 BullMQ worker is started separately from the API with `npm run worker:embeddings -w @mentorloop/api`. Start local PostgreSQL and Redis first with `npm run infra:up`; Redis uses the existing `REDIS_URL` (local Docker Compose exposes port 6380). Profile saves add delayed jobs with a 1.5-second debounce, exponential retry, and a per-profile deduplication key. During active processing BullMQ retains only the latest follow-up. The worker fetches the latest database state and holds a shared profile-row lock while validating the version and atomically writing the vector and SHA-256 hash of the exact whitespace-normalized model input. A stale inference result is discarded.

Backfill existing startup and mentor profiles in batches of 100 using the same queue. Preview candidates without enqueueing: `npm run embeddings:backfill -w @mentorloop/api -- --dry-run`. Enqueue missing or stale vectors: `npm run embeddings:backfill -w @mentorloop/api`. Both commands print only counts, not profile data.

Run fast mocked and database/Redis-backed embedding tests after migrations with `npm test -w @mentorloop/api`. Run the model similarity integration test separately (downloads the model on first use): in PowerShell, `$env:RUN_MODEL_INTEGRATION = '1'; npm run test:embedding-model -w @mentorloop/api; Remove-Item Env:RUN_MODEL_INTEGRATION`.
